## GPU semantics

`scripts/control/node.py:16-23` assigns static service dependency UUIDs. Both retained frontier identities depend on `GPU-69acfa26-8b60-61b5-702d-aee252c163cc`. These constants produce `services[].required_gpu_uuids` and `gpus[].affected_services` (`205,270`); neither is a GPU process measurement. Actual GPU telemetry carries `uuid`, `index`, `name`, `pci_bus_id`, memory/power/temperature/ECC/PCIe values plus its own envelope. Node projection selects by UUID and rejects ambiguous duplicates (`256-276`), never ordinal substitution.

Status may describe a **fresh observed service using required GPU UUID X**, joined to a fresh measured GPU X. It must not claim GPU-process attestation that the DTO does not contain. Dormant GLM belongs in impact/dependency lists, not an active-model list. GPU metrics can be stale independently of service identity. A missing measured GPU must remain missing/unknown even when a configured dependency UUID exists.
