# I1c remaining installer checklist

I1b supplies bounded source, not a complete installer. No checklist marker alone
may establish READY. Required coordinator integrations, in order:

1. **I1R/L1 package admission and ownership**: import canonical lease once;
   authorized export of the same open flock description to the package watcher;
   close-only release; recovery/admission must reconcile protected transaction
   markers before mutation. Integrate actual reviewed Runner/Prerequisites source,
   the new read-only observations, and anchored package marker I/O. Do not remove
   the explicit I1b public package checkpoint merely because method names exist.
2. **Long runtime command ownership**: extend reviewed supervision to Git/build/
   pull jobs after installer SIGKILL; cancel daemon-side build work or retain
   ownership until quiescent. Current caught-timeout process groups do not prove
   parent-loss safety. Exercise real Linux inherited-FD/source/build commands.
3. **I1S blank disk**: use the exact standalone handoff in
   `docs/orchestration/i1s-storage-handoff.md`; assign no concurrent storage.py
   editor. Implement protected partial-disk ownership and disposable Linux tests.
4. **Release/source protection**: root-owned installed code, exact source/lock
   identity, safe explicit source/lock/state upgrade migration. Existing I1/I1b
   state cannot resume from changed source by deleting its hashes.
5. **Container integration acceptance**: actual Ubuntu24.04 amd64 snapshot solver,
   policy/CDI masks/restoration, private bind interoperability, effective daemon
   roots and logs. Existing active containerd adoption needs actual daemon-root
   observation or a fail-closed adoption policy; parsing config alone cannot
   prove the running daemon loaded it. Run actual GPU container gate separately.
6. **F1S native auth**: exact reviewed wrapper/profile SHA; native pinned-image
   sentinel credential proof before production secrets. Runtime/source/CLI
   fixtures do not establish this gate.
7. **L1 lifecycle**: borrow canonical lease through existing Manager; validate
   registry/root identities and I1b acquisition/runtime contracts; protected API
   key/instance continuity, mount-bound boot, stopped intent, bounded restart and
   rollback. Preserve one active model/backend and localhost API defaults.
8. **U1 control service**: provision the reviewed authenticated model catalog/
   switch service over existing Manager; private key reference, protected source,
   service/mount ordering. No competing manager and no browser UI on the server.
9. **V0 client**: explicit ordinary user and trusted workspace; locked Node/npm/
   OpenCode, safe staged partial-prefix promotion/resume, key file reference and
   SSH tunnel access. No client/agent execution as installer root or on the
   inference-only role. Do not edit V0 source without its owner/review.
10. **Actual chosen-role acceptance**: health/live versus ready, exact catalog/
    model identity, unauthenticated rejection, bounded generation and streaming,
    structured tool request/result continuation, and ordinary-user real OpenCode
    read/edit/test loop. Server role never runs local agent tools; record any
    selected external client requirement explicitly pending until demonstrated.

Only after the above required selected stages exist and pass their postconditions
may full apply/resume run and READY be emitted. Record synthetic/macOS, disposable
Linux, actual GPU, service/client and fresh reboot results separately. No current
live ai-vm access/adoption/restart/download is authorized by this source handoff.

The only acquisition roster is GLM11 shards and Qwen48 artifacts. No DeepSeek,
new smoke model, Qwen3.8 weights, legacy cleanup or third download belongs here.
