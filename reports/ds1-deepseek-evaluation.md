## Decision and capacity

**Conditional GO for one experimental trial after GLM/Qwen acceptance; NO-GO for deployment or download now.** Best candidate: the pinned implementation-author llama.cpp fork, host-RAM Engram and CPU experts, with dense layers split across the two GPUs. This has relevant code, but Linux/two-SM120 execution, protocol correctness and useful speed remain decisive unknowns. DS1 authorizes no weights, builds or service changes.

The [official checkpoint](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash/tree/dba1be0a40aa45a94ad051997016db3960a90277) remains **`dba1be0a40aa45a94ad051997016db3960a90277`**, last modified **2026-09-10 08:18:10 UTC**; repository created that day at 02:17:58 UTC. MIT covers code and weights. Correct R2's size label: **48 safetensors shards = 510,296,708,312 bytes = 475.25 GiB**; all 88 repository files total **510,313,353,565 bytes**. Index tensor payload is 510,286,023,000 bytes, excluding file headers. Metadata was checked; weights were not downloaded or hashed.

The card describes **552B backbone + 196B conditional Engram parameters**, approximately 748B combined; **8B prefill / 16B decode** are active compute counts, not weight residency. HF's 763.205B tensor-accounting figure includes auxiliary tensors and is not the advertised backbone count. [Config](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash/blob/dba1be0a40aa45a94ad051997016db3960a90277/config.json) specifies dynamic FP8, 32×32 blocks, UE8M0 scales and FP4 experts; BF16/F32 auxiliaries also exist. Packed FP4/I8 storage must not be interpreted as ordinary INT8 inference.

Two FP8 Engram tables contain **196,613,849,600 values**; with one-byte scales per 32 values they occupy **188.83 GiB**, excluding projections. The index assigns only Engram tensors to shards 47–48, totaling **203,073,077,576 bytes / 189.13 GiB**, including projections/scales/headers. [Reference allocation](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash/blob/dba1be0a40aa45a94ad051997016db3960a90277/inference/model.py#L296).

With established **881.78 GiB RAM**, the entire packed checkpoint leaves **406.53 GiB nominal RAM headroom**. Two RTX PRO 6000 Blackwell 97,887-MiB GPUs total 191.19 GiB: weights exceed this by 284.07 GiB; a provisional 160-GiB GPU weight budget leaves at least 315.25 GiB on host. These are capacity arithmetic, not allocations: exclude conversion/dequantization, duplicate loading/page cache, pinned buffers, activations, KV/index/SWA state, workspaces, fragmentation and concurrency. The advertised 890-byte/token global KV is not total runtime memory or a fork guarantee. Threadripper PRO 9985WX; no NVLink; user-reported eight-channel DDR5-6400/~400 GB/s is unmeasured. CPU experts may be bandwidth/NUMA limited; GPU splitting adds PCIe transfers.

## API and baseline comparison

CED means a 20-layer causal encoder plus 20-layer decoder; **prompt encoding is a separate integration requirement**. There is no released Jinja template. [Official encoding](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash/blob/dba1be0a40aa45a94ad051997016db3960a90277/encoding/README.md) uses spaced DSML calls/invoke/parameter tags, qualified tool namespaces, raw strings and JSON for nonstrings. Preserve reasoning across tool-result continuation. Reuse generic OpenAI transport and client safeguards, but require a **new V4.1 protocol adapter** or prove the runtime's exact implementation; GLM/Qwen parsers are insufficient.

Official [`deepseek-recipe@8cadfede`](https://github.com/deepseek-ai/deepseek-recipe/tree/8cadfede7063c896b944e7bae05daa3549ae97ea), source version 0.1.0, converts Chat Completions/Responses/Messages and parses complete/streamed output; inference, HTTP and tool execution remain external. Reference effort accepts 1–100; recipe API schemas accept string enums, mapping low/high/max to 50/75/100. Validate adaptation and rejection of thinking plus forced/required tool choice. Responses previous-response retrieval/encrypted reasoning are unsupported: send complete history. Reject unsupported fields/server tools. Reassemble streamed calls by ID/index, validate arguments, execute once on the client and return matching results. Initial trial rejects images/remote image URLs: vision adds preprocessing, tower/workspace memory and up to 1,024 tokens/image; text-only requests do not prove vision weights are unloaded.
