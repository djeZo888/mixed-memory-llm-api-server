Local Sova compaction uses the normal Responses path with an empty current tool set while retaining historical call/result input. `thread/compact/start` ACK only means the operation was submitted. Trusted completion requires canonical item lifecycle, terminal turn status, exact descendant/container cleanup, token revocation and owned gateway settlement. The App Server item exposes only its ID; automatic/manual reason and phase are present in canonical model-request metadata, not the item. A worker-owned manual RPC proves manual intent; an arbitrary request for a “summary” proves nothing. Fixtures verify prompt prose cannot create compaction activity. No AUTO event or summarizer request was captured live here.

Pre-turn compaction uses the stored context estimate before recording the incoming prompt; the source contains a pending-input estimation TODO. Mid-turn compaction occurs when continuation is needed and the threshold/new-window condition is reached. Optional post-turn compaction has a separate failure policy. Context-window overflow during compaction trims the **cloned request input** from the oldest item and resets the ordinary retry count; it is not limited by `stream_max_retries=0`. This can omit facts from the summarizer input even while original records remain recoverable.

Replacement retains newest user text up to **20,000 approximate tokens** plus the generated summary; an older selected message can be truncated. This is not a summary-token budget or universal fact-retention guarantee. Manual/pre/mid-turn output items can enter live history and the rollout **before** `response.completed`. Those paths select the last assistant message in session history with an empty fallback and do not require a nonempty newly generated summary. Post-turn stages output until stream completion and rejects an empty new summary; that scoped staging behavior does not establish atomic persistence or rollback.

**Atomic rollback is NOT_PROVEN.** Native live history replacement precedes checkpoint append. Append failure returns a boolean and does not restore the prior live history. A terminal flush failure emits a warning and can still complete. Normal compaction appends a checkpoint to the original rollout rather than deleting its old records; cold resume reconstructs model-visible context from the selected surviving checkpoint plus suffix. A process death between live replacement and durable writes can therefore leave a different recovered context. Cancellation uses a token, **100 ms** grace, abort and attempted interruption-marker flush; it does not undo an installed summary. Transport success is not semantic grading or guaranteed disk durability.

`PreCompact` runs before candidate generation and receives transcript/model/trigger references. `PostCompact` runs after replacement. No candidate-summary semantic veto between generation and installation was found in the inspected local path. The bounded proposal is checkpoint-backed recovery or separately reviewed staging, not an invented atomic commit.

Native default stream idle timeout is **300,000 ms**, ordinary stream retries **5** (cap **100**). The tracked Sova configuration instead has idle **28,800,000 ms** and retries **0**. Adapter RPC timeout and interrupt-terminal timeout each default to **15,000 ms**; they are distinct from the native idle timeout. No independent total compaction deadline is added.
