# F1A: SGLang 0.5.14 file-auth adapter design
1. Review-only evidence: installed image `sha256:5027e95bf6ec536856b1b52a91d1f35ff5c564ab83e8a94758a169ff09bb8df3`, source files under this task's `sglang-source/`; no implementation/tests/VM access by reviewer.
2. **Recommend the native ASGI helper in a pinned, single-tokenizer launcher; no gateway is needed if the following launch-path tests pass.**
3. In guarded `main()`, parse nonsecret options, assert `ServerArgs.api_key is None` and `admin_api_key is None`, read the private key separately, then call `add_api_key_middleware(http_server.app, api_key=key, admin_api_key=None)` before `http_server.launch_server(args, execute_warmup_func=...)`.
4. Require `tokenizer_worker_num=1`, ordinary HTTP/Uvicorn, no Ray/gRPC/encoder-only/HTTP2/reload/multiple HTTP workers, no tool-server/plugins or secondary service listener; reject unsupported modes before launch.
5. The installed `_setup_and_run_http_server` retains the same module-global FastAPI object (`http_server.py:2251-2399`); adding middleware preserves its routes, lifespan and state instead of replacing `app` with a different wrapper object.
6. Setup may add a second native layer with both keys unset because admin-force routes exist (`:2301-2310`); normal requests pass that layer then meet the preinstalled key layer, while admin-force routes remain denied. Test that exact combined chain.
7. Do not briefly assign a real key to ServerArgs, clone it into a dataclass, put it in YAML/argv/environment, or rely solely on log filters: startup repr and `/server_info` serialize that object (`engine.py:784`, `http_server.py:700`).
8. Keep file reading and middleware installation inside `if __name__ == '__main__'`; multiprocessing uses spawn (`engine.py:1322`) and reimports the launcher. Child import must not reread keys, launch servers or register middleware; only key-free ServerArgs goes to GPU workers.
9. **Warmup is mandatory to handle explicitly:** stock `_execute_server_warmup` obtains Authorization only from `args.api_key`, then calls protected `/model_info` and `/generate` (`http_server.py:1968-2072`); leaving args empty otherwise causes repeated 401s and eventual process termination.
10. Prefer a small supplied `execute_warmup_func` that uses the separately held key in request headers, bounded waits and a tiny generation request, marks `ServerStatus.Up` only after success, and returns/fails with generic diagnostics without headers/body/exception dumps.
11. Do not mutate shared `requests` globals, bypass auth for loopback warmup, or install auth only after readiness; each creates a race or unauthenticated interval.
12. Alternative minimal policy: set `skip_server_warmup=True` and require a separate authenticated generation acceptance before manager readiness; `/health` or `/v1/models` alone must not be presented as generation proof in that mode.
13. Read an owned, regular, nonsymlink, mode-0600 key through `O_NOFOLLOW`, bound length, validate ASCII/no newline, and mount only the key file read-only; generic errors must not include file contents. A redacted-repr token wrapper is optional defense for middleware diagnostics.
14. Native auth passes non-HTTP scopes unchanged (`auth.py:170`), and `/v1/realtime` exists (`http_server.py:1702`): explicitly reject WebSocket scopes for this Chat Completions-only profile rather than silently exposing an unauthenticated route.
15. Native `/health*`, `/metrics*`, and OPTIONS exemptions are real (`auth.py:96-100`); document the exact intended public probes and test them. Do not describe all endpoints as authenticated.
16. Sentinel tests must assert absence from ServerArgs repr/asdict, `/server_info` and `/get_server_info`, launcher argv/environment, rendered Docker config, captured startup/failure logs, and serialized worker arguments; use no real credential.
17. Installed-source startup test must stub model/worker startup, execute the real setup path, capture the final ASGI app passed to Uvicorn, and prove missing/wrong/correct tokens on `/v1/models`, chat and an ordinary diagnostic route; correct-token tests must reach handlers.
18. Also test unauthorized WebSocket rejection, admin-force denial, declared probe exemptions, unchanged SSE chunks/client-disconnect events, failed/timeout warmup, duplicate startup/middleware safeguards, and hard refusal of multi-tokenizer/Ray/gRPC modes.
19. If the pinned native launch test cannot prove preservation, use a separately supervised authenticated loopback gateway with private backend transport and unchanged SSE/error semantics; keep real keys entirely out of SGLang configuration. This fallback costs another owned process and readiness dependency.
