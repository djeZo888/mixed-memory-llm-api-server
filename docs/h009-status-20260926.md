## CPU placement and runtime repairs

The previous two KT pools placed 64 worker threads on guest CPUs 0–23. Flash
now uses **eight pools of eight threads**, covering all eight guest NUMA nodes
with singleton masks on CPUs 0–7 and 16–71. All 64 threads accumulated CPU time
in every measured case. The pools partition expert tensors; they do not create
eight copies of all weights.

Docker's default syscall policy also blocked the NUMA memory-policy calls. A
narrow profile adds only `get_mempolicy`, `mbind` and `set_mempolicy`; the actual
bind probe passed while privilege restrictions remained enabled. These results
prove guest CPU coverage and successful guest memory-policy calls. They do not
prove one-to-one physical-core pinning, host physical RAM locality, or saturation
of all memory channels. Full memory bandwidth does not inherently require 100%
utilization of every CPU core.

The tool-call defect was traced to llguidance treating ordinary added tool XML
tokens as special. The pinned correction preserves tokenizer IDs, vocabulary
bytes and EOS behavior. Both automatic and forced native tool calls passed.

## Measurement correction

The task recorder performed storage checks, lifecycle locking, file flushing
and full receipt rewrites synchronously for every incoming stream line. Its
reported low decode rate was therefore limited by recording work. The native
13.42/13.51-token/s windows establish that Flash was generating substantially
faster. This does **not** establish the cause of every historical GLM slowdown.

Keep heavy checks at request boundaries and telemetry outside the stream-drain
path. Buffer ordinary deltas with bounded periodic checkpoints; retain durable
ownership and terminal records. Worker2's live acceptance recorder was corrected
accordingly. No additional model benchmark was needed to demonstrate the cause.

## Native Sova workflow — PASS

The live workflow completed at **21:11:41 UTC**, using the full 17-tool roster
and the actual MiniMax engine. Qwen delegated one foreground task to Flash;
Flash read the two fixture files, wrote a correction and executed the check.
The result returned to the same parent, which independently read the edit,
reran the check and produced its final answer. No substitute/mock model was
used. A separate Qwen request completed while Flash was occupied.

The four Flash requests contained 11,555–12,439 actual input tokens. Their
active request durations were **620.3, 109.0, 44.5 and 49.3 seconds**. The first
varied tool prompt was substantially slower than the repetitive benchmark
fixture, with individual prefill chunks around 9–15 tokens/s. Later turns were
faster. The exact cause of this first-request penalty is not established; do
not assume synthetic input throughput applies to arbitrary documents or tools.

The pinned runtime forcibly disables radix prefix caching for this GLM path:
its request-local KPool tail is not restored from reused prefixes. Removing
the launch flag would not enable caching; bypassing the runtime guard risks
incorrect state. The later speed improvement therefore does not demonstrate
cross-request prefix reuse. No cache behavior was changed in this round.

Acceptance exercised shell and write tools, not every available tool. The test
used a 2,048-token output ceiling; production remains 65,536. It did not test a
full-length output, large occupied context, or new browser reconnect behavior.
All four requests settled and test-owned containers were gone before recovery.
See the [native acceptance report](../reports/h009-frontier-20260926/ACCEPTANCE-02.md).

## Time and remaining performance uncertainty

The round fixed CPU placement, blocked NUMA calls, tool-token classification and
dependency permissions. It also corrected misleading benchmark recording. The
real agent workflow took about 15 minutes, mostly its first Flash request. The
final ECC restart and model recovery took about ten minutes; image startup
needed a normal owner restart after lifecycle-lock contention. Compact receipts
preserve the earlier failures as well as the successful recovery.

The first varied-prompt delay still needs targeted investigation. Later turns
were much faster, so this round establishes usable integration, not uniform
performance for arbitrary input. Larger-context tests and supported prefix-cache
improvements belong to subsequent bounded tasks; see [TODO](../TODO.md#flash-follow-up-qualification).
