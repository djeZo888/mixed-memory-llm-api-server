## User decisions
- Both text Qwens remain 480000 context; Ada image retains Full HD generation and guarded editing. Server Blackwell is inventoried/unassigned; no image relocation/resolution expansion or new models in this release. ECC unchanged pending separate evidence.
- Each native model scheduler busy-polls for 600 seconds after most recent real work, then blocks on request events; immediate wake restarts the 600-second grace period. Use monotonic time, do not block active/queued/streaming/pending asynchronous work. Startup/warmup begins initial grace. Status/metrics probes must NOT count as work. No unloading weights/cache and no fixed sleep on active inference. Each service's work controls its own grace, not unrelated traffic to another GPU. Explain this interpretation in docs.
- Missing/faulted required hardware disables dependent services for remainder of current ai-vm boot. Service/app restart, successful late probe or manual GPU reset does not clear hardware latch; next boot + validation does. Software failure and uncertain in-flight request quarantine are distinct; no blind replay.
- / remains chat; /status read-only; /admin anonymous trusted LAN/VPN admin UI for this release. Path is NOT authentication, all reachable admin visitors have same authority. No user/login/accounts/permissions system now. status.ai-harness alias points to .61 when user LAN DNS exists; /status works by IP immediately. Preserve Host/Origin, add proper same-origin CSRF, prevent agent/task containers reaching admin/control interfaces. Backend credentials server-only, never sent to browser/task container. No user-managed API token.
- Admin actions: registered service start/stop/restart, guarded dedicated GPU reset, orderly reboot of reachable ai-vm or ai-harness. Typed allowlisted actions, operation IDs/idempotency/audit, display affected work + explicit interruption confirmation. No arbitrary shell, automatic hardware resets, Proxmox changes or offline VM power-on. Unsupported reset rejected. Existing canonical lifecycle lease/owners/storage guards remain authoritative; no competing lifecycle engine.
