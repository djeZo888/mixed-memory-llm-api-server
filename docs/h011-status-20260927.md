# H011: concurrent load stopped by cooling limits

**27 September 2026 — sustained four-model load is not qualified. The 1M Flash
test was prepared but never started.** Sova remains paused pending cooling work.

Detailed evidence: [fan-adjusted trial and recovery](../reports/h011-fourway-20260927/attempt03/RESULTS.md),
[earlier thermal stop](../reports/h011-fourway-20260927/RESULTS.md), and
[runner preparation](../reports/h011-worker2-20260927/RESULT.md).

## What happened

The workload combined a 65,536-token Flash request, repeated 262,144-token Qwen
requests on each text GPU, and qualified Full HD image generation. Configured
text capacity stayed at 480,000. One VM-side owner controlled all four clients,
with sampled temperature, power, memory, swap and error guards.

| Attempt | Outcome |
|---|---|
| Initial | Recorder assumed Ada supported Docker logs; it stopped the requests after about four seconds of client overlap. Fixed and preserved as failed instrumentation evidence. |
| Corrected | Server Blackwell reached the 85°C test cutoff after about 38 seconds; one later sample reached 86°C. |
| After user increased external fan speed | Server Blackwell again reached 85°C, stopping submissions about 49 seconds after launch. Qwen0 also reached 85°C in the retained samples. |

Fan speed adjustment was user-reported; external fan RPM was unavailable. Both
temperature stops came from the benchmark's 85°C guard. No sampled NVIDIA thermal
slowdown or hardware power-brake flag was active. All three attempts are partial;
none establishes a five-minute sustained result or completed inference quality.
The Server cutoff sample was at 01:41:51.187 UTC; Qwen0 was then 82°C and reached
85°C three seconds later. Client overlap was 48.09 seconds. Native Qwen logs show
prefill progress, but Flash had no prefill/decode log or output before the stop.
Its high CPU activity alone does not establish advancing inference.

## Power and temperatures in the fan-adjusted attempt

At **01:41:44.187 UTC**, the simultaneous three-Blackwell subtotal was
**1,335.53 W**. Ada drew **294.27 W** separately from its Core X PSU.

| Service / GPU | Power at that common sample | Observed GPU temperature range in this attempt |
|---|---:|---:|
| Flash / fast Blackwell | 91.17 W | 38–45°C |
| Qwen0 / fast Blackwell | 599.08 W | 35–85°C |
| Qwen1 / Server Blackwell | 645.28 W | 36–85°C |
| Image / Ada, separate PSU | 294.27 W | 35–73°C |

This subtotal uses one common sample, not unrelated per-device maxima. Sampling
was approximately once per second; brief transients can be missed. CPU package,
motherboard, wall power and total PSU output were unavailable. The short samples
do **not** establish sustained 2200 W PSU adequacy. Cooling prevented the intended
qualification. Workstation airflow should be checked alongside the Server GPU's
duct, because both Qwen GPUs reached the test cutoff.
The separate instantaneous-power field reached a three-Blackwell subtotal of
1,388.92 W at 01:41:39.186 UTC; it is also GPU telemetry, not PSU or wall power.

Minimum available host RAM was 564.83 GiB. The fan-adjusted attempt recorded zero
host swap traffic, zero owned swap and no cgroup OOM events. GPU reserves passed.
Ordinary software power capping on Qwen0 and Ada is recorded separately from
thermal or external power-brake events.

## Recovery and current state

Closing the interrupted Flash client did not prove native work had settled. The
earlier attempts were followed by native 300-second forward-progress watchdog
exits. Their causal mechanism remains unproven. After the final stop, Worker1
used the original owner to halt the exact Flash container, verify process/GPU
release and resume it. No new load test followed.

The final handback at **01:45:16 UTC** confirmed all four native services ready,
all three text pools at 480,000, image idle, no established model client sockets
and the benchmark unit inactive. The 01:44:35 idle GPU sample showed Qwen0 47°C,
Flash 49°C, Ada 43°C and Server Blackwell 39°C, with all GPU utilization at zero.
At 01:46:02 they had cooled further to 43°C, 42°C, 40°C and 37°C respectively.
Hardware latches were unchanged and empty. Runtime/model/source pins, power
limits, ECC, CPU placement, storage guards and user data were preserved.
No kernel GPU/PCIe failure, OOM, new ECC error or guest reboot was recorded.

**Sova's application remains paused**, preventing new chat work from reaching
the GPUs. Search, status and administration remain available. Backend readiness
does not qualify these GPUs for sustained concurrent load with current cooling.

## 1M preparation and next step

The [guarded runner](../reports/h011-worker2-20260927/manual/README.md) passed
29 focused offline checks. Root reviewed the context-only wrapper changes,
manifest hashes, ownership, exact cleanup and independent request deadline.
It has **not** been staged or executed on ai-vm. Its planned trial is exactly
1,000,000 native input tokens plus up to 1,024 output tokens, under a 1,048,576
configured capacity and a two-hour main-request limit.

The native 300-second watchdog measures lack of forward progress, rather than
total request duration; it stays unchanged. The earlier 64K timing gives only a
linear input-time reference of about 63 minutes. Actual 1M speed, memory and
correctness remain untested.

After cooling is improved: repeat the bounded concurrent-load qualification,
then start the independent 1M job. **On verified 1M success, retain 1M loaded**
for the already-authorized production/Sova promotion. Restore 480K only if that
future candidate fails or times out. No long-running test is active now.
