# H008 phase 1: Server Qwen1 and Flash preparation

The Qwen1 Server profile keeps the existing immutable SGLang 0.5.19 adaptive
runtime, Qwen FP8 weights and configured 480,000-token window. It binds logical
Qwen1 to `GPU-93dbfca8-ef3a-9628-a798-6a4afd0af528`; the current physical index is
3. Qwen0 and Ada placement remain unchanged. Native launcher slot `gpu1` is a
logical alias/port choice and is independent of physical enumeration.

The protected H008 transition preserves original H005 evidence and replaces
Qwen1's measurement with a fresh, source-bound proof. It rejects an old receipt,
wrong UUID, changed source, wrong native pool, missing authentication or a copied
occupied-context claim. The source and focused regression suite has 42 passing
checks. Offline fixtures are not live acceptance.

September 26 commissioning used the same runtime on the Server GPU. Native
configured context and pool both reported 480,000. Authentication and the exact
short answer `MIGRATION_OK` passed. After a discarded 16,384-token native warm-up,
one request completed with exactly 65,536 input tokens, 256 output tokens and zero
cached tokens. TTFT was 9.004 seconds; input count divided by TTFT was 7,278.8
tokens/s, including request overhead. Decode was 36.28 tokens/s. The sampled
Server GPU peak was 61,637 MiB used, minimum free 35,615 MiB and peak temperature
60 C. The thermal cutoff was 85 C. CPU temperature was unavailable. This proves
fresh allocation and a 65,792-token occupied request, not near-full 480K use.
Production publication and current runtime state are recorded separately in the
private H008 task handoff; do not infer current readiness from this source note.

Flash preparation follows the [official KT tutorial](https://github.com/kvcache-ai/ktransformers/blob/c40722bf04c494f2492b7eb9e86ef01a4ede45b3/doc/en/kt-kernel/GLM-5.3-Flash-Tutorial.md).
The official FP8 model revision is
`eb9eb208eb0d988989d07a6a12d0fdeb5f52574a`; 62 shards and seven required metadata
files total 328,366,161,957 bytes. No extra quantization or old-weight changes are
part of this task. The [model declaration](../configs/models/glm-5.3-flash-fp8.json)
contains exact HF sizes and content identities. The separate
[build recipe](../scripts/runtime/flash/Dockerfile) pins an independent CUDA 12.8,
SM120-capable base and seven primary wheel artifacts, including tokenizer and
Jinja versions used by the offline fixtures. Final image and complete dependency
receipts are required before activation.

The [Flash candidate](../configs/deployments/glm-5.3-flash-480000-fp8-kt.json) is
preparation only and is not registered with the production Manager. Context and
native token pool are both targeted at 480,000, with one active request, 64 CPU
expert threads, two NUMA-spread thread pools and no resident GPU experts. Its
actual peak must retain at least 7% free VRAM on the freed fast Qwen card and 15%
available host RAM. The static memory fraction alone is not that proof.

Root's revised test scope is 4K warm-up, 4K/16K measured inputs and an optional
short-input 2,048-token decode test. No 64K Flash input or larger context sweep is
included. Text-only tokenization must reproduce the native template and tool
history normalization. Independent lifecycle/status/boot handling, authenticated
transport, exact native tokenizer endpoint, 600-second grace followed by blocking
idle, and exclusion of the historical full GLM while Flash is reserved remain
activation prerequisites. The newer Qwen idle overlay cannot be applied unchanged
to this KT scheduler layout. No Flash live inference acceptance is claimed here.
