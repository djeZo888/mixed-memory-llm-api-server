Only the exact two declarations can coexist. Historical TP2/1M and native
singleton profiles remain available as mutually exclusive alternatives. The
validator checks whole profile/model/runtime bytes, so operators cannot supply
different capacities, GPU indices, flags, defaults or resource caps as launch
arguments. A different accepted capacity or cap requires a reviewed profile and
corresponding source pin update. Guest CPU partitions do not establish physical
CPU pinning.

The Qwen pair uses one additive wrapper,
`scripts/runtime/sglang38_pair_file_auth.py`, mounted read-only at
`/opt/llmctl/sglang38_pair_file_auth.py`. It imports the unchanged SHA256-pinned
base launcher from its existing read-only mount and exposes no launch arguments.
The wrapper checks the exact changed context/TP fields and reuses the base's
raw/resolved native checks, native authentication, cancellation and cleanup.
Older launcher bytes, native profile arguments and actual-image auth receipts
are retained. They do not attest the new pair wrapper.

## Protected acceptance contract

No acceptance receipt is included or generated by this source task. Root must
review actual benchmark/allocation evidence and the final shipped source before
a separate activation session installs one. The fixed location is the registered
data root plus `services/llm-manager/evidence/concurrent-g1q1.accepted.json`.
The existing registered binding requires protected ancestry, a root-owned
single-link regular mode-0600 file, mount identity and anchored read validation.

The protected instance references it as `concurrent_pair_acceptance` with exactly
`path`, `sha256` and `reviewed_source_commit`. The digest is SHA256 of UTF-8 JSON
serialized with sorted keys and separators `(',', ':')`, without NaN. It is
checked against the actual protected file; a path or instance flag alone is
insufficient.

`concurrent_profiles.check_acceptance()` validates and returns the receipt. Its
required fields are:

| Field | Required content |
| --- | --- |
| `schema_version`, `kind`, `status` | Integer 1, `root-reviewed-concurrent-g1q1`, `ACCEPTED_FOR_ACTIVATION` |
| `instance_id`, `storage_identity` | Exact current instance and registered binding identity |
| `reviewed_source_commit` | Same 40-hex commit as the protected instance reference |
| `source_sha256` | Exact current critical source map returned by `source_identity()` |
| `gpu_inventory` | Exact index/UUID pairs for GPU0 and GPU1 above |
| `concurrency_performance_review`, `evidence` | `ACCEPTED`; nonempty reviewed evidence references |
| `host_usable_bytes` | Measured usable host capacity sufficient for both caps |
| `slots` | Exactly `glm` and `qwen`, each with the fields below |

Each slot binds `deployment`, `configured_context`, `profile_sha256`,
`runtime_image_id`, `model_revision`, `visible_cuda_devices` (`CUDA0` to its actual
UUID), `guest_cpu_count`, `guest_cpuset`, `memory_bytes` and `memory_swap_bytes`.
Actual `allocation`, `short_inference` and `correctness` must each be `PASS`.
`largest_occupied_context` is a separate positive integer no larger than configured
capacity; allocation acceptance cannot claim that all configured tokens were
occupied or retrieved correctly.

Each slot also supplies defensible measured `host_peak_bytes`,
`minimum_free_gpu_bytes` and `gpu_total_bytes`. Host caps must retain at least 25%
above measured nonoverlapping demand; aggregate caps must fit usable host memory.
Both GPUs must retain at least 16 GiB free and Qwen must additionally retain at
least 10% of physical GPU capacity. Review must identify the counters and phases
behind these measurements rather than adding overlapping RSS/cgroup/file/shmem
counters.

Qwen additionally requires `pair_launcher_sha256` and `native_auth_checks`
containing `PASS` for each existing `qwen38.AUTH_CHECKS` gate, from actual native
execution of the new wrapper. Source fixture results cannot supply this receipt.
Missing, malformed, mismatched or incomplete evidence refuses pair start/create.
Actual host GPU inventory is rechecked at lifecycle admission; Docker create and
reuse require the exact UUID, CPU, no-swap and visible-CUDA contract.
